# VC 数量以外的性能限制与理论基准（2026-11-04）

<!-- Modify by Michael Tan，20261104: separate proven non-count limitations from ruled-out scheduler explanations using exact snapshot matching. -->

## 结论

当前不能把性能优化理解为只扩VC数量。还要区分包级资源预约/归还协议、逐跳包头启动时序、源队首阻塞、调度效率、路由负载和流控粒度。但本次观测也排除了若干看似合理的主因：当前Torus高负载点的SA/VA仲裁接近同一候选请求图的最大匹配，FIFO满和SA on_off等待均为0，不能把巨大差距归给仲裁器或存储深度不足。

低负载与高负载要分别评价。低负载Torus约11.44周期的在网均延迟已接近当前RTL无竞争下界约10.95周期；25倍总延迟不是所有负载下都比理论差25倍，而是高负载服务不足造成源队列持续增长。扩VC后能否消除该问题、届时调度是否成为新瓶颈，尚未验证。

新增4组scheduler_profile沙箱外Vivado2025.2仿真全部PASS，每组11889包/47556flit，共47556包/190224flit。与前轮观测逐字节核对trace、packets、summary、stalls、vc_profile、port_profile，全部一致；正式RTL未改。

## 1. 调度：确有机会损失，但当前Torus中很小

现有两级输入优先仲裁先在每个输入端口选一个VC，再在输出端口竞争。若两个输入都选同一出口，其中一个失败，第一阶段不会改试该输入的另一个候选出口。RR的第一阶段优先级也按本阶段选择更新，不等最终授权成功；这可产生不理想的调度，但不能仅凭源码就宣称是本次主因或存在无界饥饿。

新增独立观察器逐路由器、逐周期构建SA候选图：候选必须真的有switch_request、锁定的SA出口和VC必须on_off开启；每个物理输入/输出最多一条传输。用完整搜索得到最大匹配，再与实际授权比较。VA同理，先过滤allowed&available，再按当前VA每物理输入/输出最多一条授权的相同约束求最大匹配。

固定源VC策略、1001～4000周期、25路由器合计结果：

| 项目 | Mesh | Torus |
| --- | ---: | ---: |
| SA实际授权 | 155476 | 95690 |
| 同周期候选图最大匹配之和 | 164441 | 95932 |
| SA实际/最大匹配 | 94.548% | **99.748%** |
| VA实际授权 | 38860 | 23921 |
| 同约束VA最大匹配之和 | 38949 | 23977 |
| VA实际/最大匹配 | 99.771% | **99.766%** |

可用源VC策略下Torus SA/VA分别99.669%/99.581%，结论类似。当前Torus实际SA比理想快照调度少242次，不能直接由此解释源队列数千包和总延迟约800周期。Mesh SA少8965次，说明同一仲裁器并不是在Torus中出现了特别严重的调度效率下降。

上述比值仅针对“本来已经具备资源资格的请求”。它不包括被VC资格挡在候选图之外的请求。也不是使用最优调度后全网只能改善0.252%的严格因果上界：改调度会改变后续状态和请求。扩VC后候选图可能变密，现有SA的损失也可能变大，需要重新测，不能外推当前99.75%到16VC方案。

## 2. 包级预约/归还是独立于VC数量的协议开销

当前VC归还发生在下游TAIL读出之后，依次经过归还通知、上游availability寄存更新和下一包VA登记。一个包在上游链路已经发送结束，不等于它占用的下游缓冲资源已经归还。即使下游FIFO还有空位，另一个包也不能直接按“未满”接入。

这是VC**使用协议和资源周转周期**，不是单纯的VC数量。更多同类VC可以隐藏开销，但并不消除开销。前轮无竞争单跳实测4flit每包4周期空隙，16flit仍4周期空隙，证明短包对该协议尤其敏感。

当前包缓冲支持逐包metadata，但上游所有权只在TAIL读出归还，使同一VC实际接入流难以利用深度8去排两份四flit包；增加FIFO深度并不会自动放开包级接入。若后续研究TAIL写入后安全归还，需要同时验证上游写流所有权、metadata容量/接收背压、完整包边界和新的通道依赖假设，不能只改归还脉冲。这是独立设计任务，本次没有修改协议。

预分配后暂时缺flit也可能白占下游VC。新增计数显示Torus固定策略在窗口内有2180个“本输入队首已获配、flit FIFO暂空”的输入VC周期；Mesh为51155。该单位不同于包延迟，也不是所有预约都被浪费的时间。Torus对应无预约但非空的请求周期160578，当前证据不支持把缺flit导致的提前预约浪费视为其主要退化来源。

Dally的VC流控工作强调缓冲资源与传输资源解耦，以使可前进的包绕过阻塞包，而非仅增加队列个数：[原论文](https://groups.csail.mit.edu/cag/PSRG/papers/dally-ieee92.pdf)。本项目需要检查协议是否让这种并行能力实际发挥。

## 3. 每跳固定时序限制低负载延迟

当前包头写入FIFO和metadata后，下一周期登记VA结果，再下一周期才首次SA转发。RC是写入前组合计算，并非额外再独立增加一个寄存周期。包头首次跨每个路由器约2周期，之后还要计包长的串行发送；理想无竞争情况下：

```text
入网后TAIL延迟下界 = L + 2×(H+1)
L：包长；H：物理网络跳数；+1计入源路由器与最终LOCAL弹出。
时间按HEAD写入至TAIL收到的包含端点周期计算，与当前TB一致。
```

这不是任意NoC的通用理论公式，而是当前RTL时序的无竞争下界；全部16个原均匀负载/种子案例的每个采样包都满足实际在网延迟不小于该下界。

0.01包/节点/周期、种子1的实际采样路径为：

| 项目 | Mesh | Torus |
| --- | ---: | ---: |
| 样本平均跳数 | 3.226 | 2.473 |
| 当前RTL无竞争平均下界 | 12.452 | 10.947 |
| 实测入网后均延迟 | 12.729 | 11.441 |
| 超出下界 | 0.277 | 0.494 |
| 源排队 | 0.073 | 0.086 |

因此低负载并没有离本实现的合理下界很远。拓扑平均跳数减少约25%，并不意味着总延迟减少25%；固定端点启动和4flit串行发送仍存在。要进一步降低无负载延迟，需研究VA/SA重叠或lookahead等结构，而不仅是增加VC；但这些改动会改变关键路径、时钟频率和验证范围，尚未实施或综合。

高负载0.12种子1，Torus同样路径下的无竞争下界约11.014、实际入网后30.089、源排队770.843。严重偏离来自资源等待与源排队，而非固有启动延迟从11变成800。

## 4. 源端单游标与固定接入策略

原TB每个源只有一个有序包游标，按全局id%4固定接入VC，阻塞时不绕过。选择可用VC后仍不能越过队首包，只减少因指定接入VC忙而空等的机会；源只有一个正在发送的包。

前轮同轨迹反事实：Mesh31.616→27.413，Torus800.932→614.187，证明固定VC策略放大总延迟，但不是完整原因。要单独评估源队首阻塞，后续应建立每VC独立源队列/游标的受控对照，并保持出生轨迹、合法包内锁定和相同总队列容量；目前尚未测试，不能承诺会消除剩余差距。实际CPU/RN接口是否允许包之间重排也必须按接口语义确定，不能仅为改善图表改TB。

0.12对应名义0.48flit/节点/周期，低于源物理端口1flit/周期上限，所以不是原始注入带宽本来就只有0.36。源端策略与网络资源背压相互作用才形成积压。完全排空也没有消除出生窗口样本曾经经历的排队时间。

## 5. 固定XY、流量不均与物理理论上界

固定XY不能绕过局部拥塞，面对特定非均匀流量可能限制性能；这是算法能力限制。但本次0.12均匀样本重放的最忙物理链路需求Mesh0.639、Torus0.358flit/生成周期，均未超过1，不能把当前Torus的主要问题说成某条物理链路平均需求已超载。路由自适应收益尚未做独立实验。

另一方面，“每条线1flit/周期”不是整个网络每节点吞吐的保证。按5×5、均匀非自身目的、固定最短XY路径，每源发送f flit/周期，把每源流量均分24个目的，穷举600条路径可得：

| 理想流体模型项目 | Mesh | Torus |
| --- | ---: | ---: |
| 最忙有向链路负载/f | 1.25 | 0.625 |
| 仅链路容量给出的f上界 | 0.8 | 1.6 |
| 再受单节点注入/接收1flit上限约束 | **0.8** | **1.0** |

这些上界忽略VC约束、包级周转、仲裁、突发和有限缓冲，不是已经证明可达的RTL性能或应该测得的结果。原测试最高名义输入0.48，也不是穷尽全网饱和曲线；Mesh输出0.478主要说明它服务了该档输入，不能将0.478认定为Mesh最大吞吐。

对比理论必须区分：拓扑/理想调度的容量上界、当前RTL的无竞争延迟下界、特定流量的实测窗口吞吐/源排队。将三者混为一个“理论性能”会得出不准确结论。

## 6. 流控、缓存和板级时序：本点不支持或尚未验证的因素

- 当前on/off有7关闭、降到1重开的滞回，理论上可产生批量停发；但本点两种源策略、两个拓扑的内部SA on_off等待都为0，不能作为本次巨大退化的解释。
- 本点物理FIFO满周期0。增加深度可能影响其他长包/突发案例，但不能据本次数据优先认为“缓存太浅”；包级资格未归还和物理FIFO满是不同问题。
- 单个FIFO的队首包只能沿一个已锁定出口前进，后包不能越过，属于队首阻塞；当前包级独占使多包接入受限，因此与资源周转机制相关。尚未独立量化每种HOL的因果贡献。
- Torus跨边长线可能影响实际Fmax，但当前两侧同10ns仿真时钟、链路无额外延时，没有用Windows综合/布线结果证明实际频率。不能把物理布线时序当作当前周期级退化原因，也不能把仿真10ns当作已实现100MHz时序收敛证据。

## 7. 优先级与可验证的下一步

1. 先建立每阶段相同可选VC数的对照，同时披露增加的总VC/缓存/位宽资源，避免把资源补足和拓扑收益混为一项；本次未实现8/16VC。
2. 保留现有握手，先评估类别资源组织能否隐藏已证实的包间空隙；扩VC后重新测SA/VA快照效率，不能沿用当前99.75%。
3. 若仍明显低于目标，再分开做源多队列、包级安全接入/归还时序对照。每次保持其他流量和统计条件不变，不能同时修改几种机制再声称各自有效。
4. 低负载时延若是目标，再单独评估逐跳启动重叠；仲裁优化属于后续潜在瓶颈，而非当前有证据的首要修复。
