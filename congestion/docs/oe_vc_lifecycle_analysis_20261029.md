# OE VC 生命周期与源队首阻塞分析（2026-10-29）

<!-- Modify by Michael Tan，20261029: trace VC ownership, FIFO occupancy and source serialization without changing RTL. -->

接续昨日散列消融与阶段观测。本次只读代码、复核既有CSV，未修改RTL/TB、未运行新仿真或综合；下述运行数值均来自2026-10-28历史结果。

## 1. VC占有不等于FIFO满

`congestion/src/vc_allocator.sv:75`仅允许所选输出有空闲VC的请求进入仲裁；获配时90行清可用位，99～101行收到归还脉冲后恢复。`input_buffer_src_circular_full.sv:193`已修正为注册输出meta_pop_cmd，不能沿用初次静态报告中的“未满即可重分配”描述。

释放触发条件为165行accept_read与TAIL/HEADTAIL同时成立；TAIL写入、HEAD读出或FIFO未满均不触发归还。上游预约的是下游输入VC，须等该包尾部从下游输入缓冲读出，才归还该资源。下游头包若正在等待更下一跳VC，仍持有其上游预约的VC，于是可以形成逐跳回压链。这是代码可支持的机制解释，尚无逐VC寿命直方图，不能断言实际等待链长度或其延迟贡献。

非阻塞赋值时序还意味着：尾部在边沿t读出后产生归还脉冲，上游可用位在t+1边沿恢复，随后才可参与新授权。该周转开销是共享机制，不能单独解释OE相对XY差距；不要把提前到TAIL写入释放当作无需验证的优化。

## 2. FIFO占用与流控是另一组状态

`circular_buffer_Xiugai3.sv:24`当前ON_OFF_LATENCY=2；默认深度8，递增至7关闭，递减至1重新打开，见104～109行。初始导入报告所述“满8关闭、空0打开”已不是当前代码。

VA可用位表示包预约；num_flits表示实际flit存量；on_off还带历史滞回。三者不能互相替代。包头已获配但flit暂未到、头部已离开但尾部未离开等阶段，VC预约与存量可能不同。现有阶段统计没有采集每个已预约VC的存量，因此不能声称OE大量占着空FIFO，也不能仅据SA流控等待为0推断所有FIFO都未满。

## 3. 源端存在明确的顺序发送限制

`congestion/testbench/tb_congestion_latency_compare.sv:79`起的drive逻辑，每源只有一个send_pid/send_beat游标，VC固定pid%4。只有当前包四个flit发送完毕才推进send_pid；当前指定VC的source_on关闭时，该周期停发，不扫描其他VC或后包。阶段观测TB164～193行保持相同机制。

因此四个注入VC不是四个可独立调度的软件源队列；后包即使对应另一空闲VC也不能绕行。source_release虽连接，却未参与源端HEAD选择：该TB按on_off向本地输入缓冲有序写入，允许完整包排队，与路由器之间的独占预约协议需分别理解，不能仅据未使用source_release认定错误。

这是工作负载/注入器共同条件，XY与OE完全相同，比较仍然公平；但它可能放大算法产生的局部阻塞。尚未量化可绕过源队列能降低多少延迟，不能将源排队占比直接称为源调度的独立因果份额。

## 5. 下一项观测应如何区分假设

保持原散列、回退OFF、注入器及正式RTL不变，新增独立观测TB，先在0.06对照XY/OE并精确复现原22个CSV字段。

- 对每个上游输出VC，从授权到归还跟踪预约寿命及当前占有者；区分下游等待VA、等待SA、已获配但FIFO为空等状态，单列包尾已送达但未读出的时间。
- 按相同采样边沿关联下游FIFO占用0～8与上游预约状态，另列授权/归还流水过渡，避免错位造成假空占有；记录VC编号分布，核查最低编号优先的使用偏斜。
- 在源端区分当前包HEAD等待、BODY/TAIL等待；同时记录其他VC是否on_off开启、其是否存在可发送后包。仅有其他VC开启不足以证明存在可绕过的工作。
- 分开统计生成窗口与排空期；占有尚未结束的样本需标记截尾，不能只统计短寿命的完成样本。

先确认具体占有状态，再选择源调度或资源策略单因素实验。保持TAIL读出释放的正确性边界，不直接恢复未满释放，不将当前静态分析冒充新仿真证据。
