# 分离式输入优先仲裁器（`separable_input_first_allocator`）模块代码分析

分析对象：`src/separable_input_first_allocator.sv`。本文按 RTL 源码顺序说明请求矩阵如何经过两级 `round_robin_arbiter` 变为最终 `grant_o`，并结合交换分配和 VC 分配的调用代码说明其控制作用；没有修改设计 RTL。

## 1. 模块在 NoC 中解决什么问题

一个路由器有 `PORT_NUM=5` 个端口（`LOCAL/NORTH/SOUTH/WEST/EAST`），每个端口当前有 `VC_NUM=4` 个虚拟通道。同一周期内，多个“输入端口-VC”组合可能请求同一个输出端口，但一个输出端口只能服务一个输入端口；同时，同一输入端口也不能在一个周期从多个 VC 同时发送 flit。

本模块采用 **Separable Input-First（分离式、输入优先）** 两级仲裁来满足这两个约束：

```text
request_i[输入端口][VC]
        │
        ▼
第一级：每个输入端口内，4 个 VC 做轮询仲裁
        │ vc_grant[输入端口][VC]
        ▼
按获选 VC 的 out_port_i 转成输出端口请求
        │ out_request[输出端口][输入端口]
        ▼
第二级：每个输出端口内，5 个输入端口做轮询仲裁
        │ ip_grant[输出端口][输入端口]
        ▼
grant_o[输入端口][VC]
```

“Input-First” 的意思是先在输入端口内部决定哪个 VC 有资格参赛，再在输出端口竞争中决定哪个输入端口真正获胜。

## 2. 参数、端口和三个中间矩阵（第 3–16 行）

```systemverilog
module separable_input_first_allocator #(
    parameter VC_NUM = 4
)(
    input rst,
    input clk,
    input [PORT_NUM-1:0][VC_NUM-1:0] request_i,
    input port_t [VC_NUM-1:0] out_port_i [PORT_NUM-1:0],
    output logic [PORT_NUM-1:0][VC_NUM-1:0] grant_o
);

logic [PORT_NUM-1:0][PORT_NUM-1:0] out_request;
logic [PORT_NUM-1:0][PORT_NUM-1:0] ip_grant;
logic [PORT_NUM-1:0][VC_NUM-1:0] vc_grant;
```

### `out_port_i` 的数组声明如何理解

```systemverilog
input port_t [VC_NUM-1:0] out_port_i [PORT_NUM-1:0]
```

这是 SystemVerilog 的“数组化枚举端口”声明，可拆成：

```text
port_t                 // 元素类型：LOCAL/NORTH/SOUTH/WEST/EAST 等端口枚举
[VC_NUM-1:0]           // 每个输入端口内的 VC 维度（packed）
out_port_i             // 信号名
[PORT_NUM-1:0]         // 输入端口维度（unpacked）
```

因此代码访问 `out_port_i[in_port][in_vc]` 时，第一个下标选择输入端口，第二个下标选择该端口中的 VC：

```text
out_port_i[输入端口编号][VC 编号] = 该 VC 路由计算得到的目标输出端口
```

例如：

```systemverilog
out_port_i[2][1] = EAST;
```

表示输入端口 2 的 VC1 要走 `EAST` 输出端口。当前工程 `PORT_NUM=5`、`VC_NUM=4`，所以该信号可理解为“5 个输入端口 × 每端口 4 个 VC”的路由方向表。`port_t` 定义为 `enum logic [2:0]`，因此每个表项本质上保存一个 3 bit 端口枚举编码。

维度位置也有区别：写在信号名前的 `[VC_NUM-1:0]` 是 packed 维度，写在信号名后的 `[PORT_NUM-1:0]` 是 unpacked 维度；但对本模块的功能理解而言，最重要的是索引顺序始终为 `[输入端口][VC]`。

| 信号 | 下标含义 | 作用 |
| --- | --- | --- |
| `request_i[p][v]` | 输入端口 `p`、该端口的 VC `v` | 上游表示该 VC 希望使用其路由确定的输出资源。 |
| `out_port_i[p][v]` | 输入端口 `p`、VC `v` | 该请求希望到达的输出端口枚举值。它不是本模块计算的，而是上游路由计算提供。 |
| `vc_grant[p][v]` | 输入端口 `p`、VC `v` | 第一级结果；每个 `p` 最多一个 bit 为 1。 |
| `out_request[o][p]` | 输出端口 `o`、输入端口 `p` | 第一级胜出的 VC 已转换成“输入端口 `p` 请求输出端口 `o`”。 |
| `ip_grant[o][p]` | 输出端口 `o`、输入端口 `p` | 第二级结果；每个 `o` 最多一个 bit 为 1。 |
| `grant_o[p][v]` | 输入端口 `p`、VC `v` | 最终结果；只有同时赢得两级的输入 VC 为 1。 |

注意 SystemVerilog packed 向量的第一个下标在左侧：例如 `request_i[p][v]` 可直观理解为第 `p` 个输入端口中的第 `v` 个 VC 请求。

## 3. 第一级代码：每个输入端口内的 VC 轮询（第 23–37 行）

```systemverilog
genvar in_arb;
generate
    for(in_arb=0; in_arb<PORT_NUM; in_arb++)
    begin: generate_input_round_robin_arbiters
        round_robin_arbiter #(
            .AGENTS_NUM(VC_NUM)
        )
        round_robin_arbiter (
            .rst(rst),
            .clk(clk),
            .requests_i(request_i[in_arb]),
            .grants_o(vc_grant[in_arb])
        );
    end
endgenerate
```

`generate for` 不是运行时循环，而是在 elaboration 时生成 `PORT_NUM` 个硬件仲裁器。当前参数下会生成 5 个一级仲裁器，每个仲裁器有 4 个竞争者：

```text
一级仲裁器 in_arb=0：request_i[0][3:0] → vc_grant[0][3:0]
一级仲裁器 in_arb=1：request_i[1][3:0] → vc_grant[1][3:0]
...
一级仲裁器 in_arb=4：request_i[4][3:0] → vc_grant[4][3:0]
```

因此即使 `request_i[2][0]` 和 `request_i[2][3]` 同时为 1，`vc_grant[2]` 也只能有一个为 1。这保证一个输入端口在一个周期只选出一个待发送 VC。每个一级仲裁器各自保存 round-robin 指针，VC 间的公平性彼此独立。

## 4. 第二级代码：每个输出端口内的输入端口轮询（第 44–58 行）

```systemverilog
genvar out_arb;
generate
    for(out_arb=0; out_arb<PORT_NUM; out_arb++)
    begin: generate_output_round_robin_arbiters
        round_robin_arbiter #(
            .AGENTS_NUM(PORT_NUM)
        )
        round_robin_arbiter (
            .rst(rst),
            .clk(clk),
            .requests_i(out_request[out_arb]),
            .grants_o(ip_grant[out_arb])
        );
    end
endgenerate
```

这里再生成 5 个仲裁器，但每个仲裁器的竞争者数为 5 个输入端口，而不是 VC：

```text
输出端口 EAST 的仲裁器：out_request[EAST][4:0] → ip_grant[EAST][4:0]
```

若输入端口 0、2、4 都希望使用 EAST，则它们在这个二级仲裁器中轮询。`ip_grant[EAST][2]=1` 表示 EAST 输出本周期选择来自输入端口 2 的路径。

## 5. 组合逻辑：把两级结果连接起来（第 71–103 行）

### 5.1 默认清零（第 71–74 行）

```systemverilog
always_comb
begin
    out_request = {PORT_NUM*PORT_NUM{1'b0}};
    grant_o= {PORT_NUM*VC_NUM{1'b0}};
```

每次组合计算先清空中间输出和最终输出：没有一级 VC 胜者时不会有二级请求；没有两级同时获胜者时不会产生最终授权。这也避免保留上一次组合计算的值。

### 5.2 从 `vc_grant` 生成 `out_request`（第 76–86 行）

```systemverilog
for(int in_port = 0; in_port < PORT_NUM; in_port = in_port + 1)
begin
    for(int in_vc = 0; in_vc < VC_NUM; in_vc = in_vc + 1)
    begin
        if(vc_grant[in_port][in_vc])
        begin
            out_request[out_port_i[in_port][in_vc]][in_port] = 1'b1;
            break;
        end
    end
end
```

这段代码只查看每个输入端口的一级胜者。假设：

```text
vc_grant[1][2] = 1
out_port_i[1][2] = EAST
```

则执行赋值：

```text
out_request[EAST][1] = 1
```

含义从“输入端口 1 的 VC2 获选”转换为“输入端口 1 请求 EAST 输出端口”。`break` 与一级仲裁器的 one-hot 保证相一致：一个 `in_port` 找到自己的唯一胜者后停止，不能为多个输出端口同时发请求。

### 5.3 合并 `vc_grant` 与 `ip_grant` 得到 `grant_o`（第 88–101 行）

```systemverilog
for(int out_port = 0; out_port < PORT_NUM; out_port = out_port + 1)
begin
    for(int in_port = 0; in_port < PORT_NUM; in_port = in_port + 1)
    begin
        for(int in_vc = 0; in_vc < VC_NUM; in_vc = in_vc + 1)
        begin
            if(ip_grant[out_port][in_port] & vc_grant[in_port][in_vc])
            begin
                grant_o[in_port][in_vc] = 1'b1;
                break;
            end
        end
    end
end
```

这段代码表达的是两级条件的交集：

```text
grant_o[p][v] = 1
当且仅当 vc_grant[p][v] = 1，且 ip_grant[out_port_i[p][v]][p] = 1
```

例子：一级选出 `vc_grant[1][2]=1`，所以输入端口 1 向 EAST 请求；若 EAST 的二级仲裁结果是 `ip_grant[EAST][1]=1`，最终产生 `grant_o[1][2]=1`。若 EAST 选择的是输入端口 4，则 `grant_o[1][2]` 仍为 0，输入端口 1 的 VC2 本周期不能发送。

## 6. 该模块怎样被实际调用

### 6.1 交换分配器：决定哪一个 flit 穿过交叉开关

在 `src/switch_allocator_Xiugai1.sv` 第 16–25 行，模块连接为：

```systemverilog
.request_i(request_cmd),
.out_port_i(ib_if.out_port),
.grant_o(grant)
```

上游先用第 53–56 行构造 `request_cmd`：

```systemverilog
if(ib_if.switch_request[up_port][up_vc] &
   on_off_i[ib_if.out_port[up_port][up_vc]]
           [ib_if.downstream_vc[up_port][up_vc]])
    request_cmd[up_port][up_vc] = 1'b1;
```

所以进入本仲裁器的请求已经同时满足：该输入 VC 想发送（`switch_request`）且目标下游 VC 允许发送（`on_off_i`）。最终 `grant` 在第 64–69 行驱动：

```systemverilog
ib_if.vc_sel[up_port] = up_vc;
ib_if.valid_sel[up_port] = 1'b1;
valid_flit_o[ib_if.out_port[up_port][up_vc]] = 1'b1;
xbar_if.input_vc_sel[ib_if.out_port[up_port][up_vc]] = up_port;
```

也就是说，`grant[p][v]=1` 不传递 flit 本身，却同时选择输入块的 VC、指定交叉开关输出应接哪一个输入端口、并使该输出 `valid_flit_o=1`；随后交叉开关在这些控制信号下传输对应 flit。

### 6.2 VC 分配器：决定哪个请求可占用下游 VC

在 `src/vc_allocator.sv` 第 16–25 行，完全复用本模块，但 `request_cmd` 的含义改为“请求分配一个下游 VC”。其第 75–78 行只会对目标端口至少有一个可用 VC 的请求置位：

```systemverilog
if(ib_if.vc_request[up_port][up_vc] &
   |is_available_vc[ib_if.out_port[up_port][up_vc]])
    request_cmd[up_port][up_vc] = 1'b1;
```

`grant[p][v]=1` 后，第 86–90 行选择一个具体下游 VC、置 `vc_valid` 并把该资源标记为已占用。因此仲裁算法相同，但仲裁资源由“交叉开关输出带宽”变为“下游 VC 所有权”。

## 7. 本实现的约束与时序注意点

1. **每输入端口最多一个最终胜者。** 因为一级 `vc_grant[p]` one-hot，所以某输入端口即使有多个 VC 申请不同输出，也只允许一级轮询选中的一个进入二级。

2. **每输出端口最多一个最终胜者。** 二级 `ip_grant[o]` one-hot，故一个输出端口每周期只会被一个输入端口选中。

3. **两级均为组合授权、状态在时钟沿推进。** 具体 round-robin 指针位于各 `round_robin_arbiter` 实例中。只要某实例发现请求，它会在下一时钟沿推进指针；一级获选但二级落败的 VC，一级指针也会前移，因为该基础仲裁器没有“最终接受成功”反馈。

4. **本模块依赖 `out_port_i` 合法。** 第 82 行直接以 `out_port_i[in_port][in_vc]` 作为 `out_request` 的数组索引；上游路由计算必须在请求有效时给出 `LOCAL/NORTH/SOUTH/WEST/EAST` 之一，不能为 `X` 或越界值。

5. **仲裁结构是输入优先，不是全局最优匹配。** 先筛掉每个输入端口的其他 VC，再做输出端口竞争，硬件规模较小、时序清晰；但与一次性全局匹配相比，可能错失某些能让更多端口同时传输的组合，这属于该架构的正常取舍。

## 8. 总结

`separable_input_first_allocator` 是 NoC 的共享资源选择器：它先将 `request_i[p][v]` 缩减为每个输入端口最多一个 VC 胜者，再按这些胜者的 `out_port_i` 让不同输入端口竞争输出，最后输出可直接用于交叉开关控制或下游 VC 占用控制的 `grant_o[p][v]`。其核心不是传输数据，而是把“谁请求哪条路径”的二维请求信息转成互斥、带 round-robin 公平性的控制授权。
