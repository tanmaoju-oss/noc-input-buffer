# 输入缓冲（`input_buffer`）模块代码分析

分析对象：`src/input_buffer_src_circular_full.sv`。本文严格按该文件的源代码顺序说明当前生效逻辑；第 100–255 行为已注释的旧单包 FSM，仅说明其历史原因，不参与当前综合/仿真。

## 模块功能与层级位置

`input_buffer` 是**一个输入虚拟通道（VC）的缓冲与控制模块**。它保存该 VC 到达的 flit，保存每个 packet 的路由/下游 VC 元数据，并依次完成下游 VC 分配和交换发送。

当前层级关系为：

```text
router
└─ input_block                 ：一个路由器的全部输入端口
   └─ input_port               ：一个物理输入端口
      └─ input_buffer × 4      ：VC0、VC1、VC2、VC3
         └─ circular_buffer    ：该 VC 的 flit 环形 FIFO
```

`input_buffer` 不负责计算路由，也不直接仲裁竞争：路由方向由 `rc_unit` 给出；下游 VC 由 `vc_allocator` 分配；每周期哪个 VC 可以经过输出端口由 `switch_allocator` 决定。它的职责是保存状态、发起请求，并在仲裁成功时读写 FIFO。

## 1. 模块接口（第 3–24 行）

```systemverilog
module input_buffer #(
    parameter BUFFER_SIZE = 8
)(
    input flit_novc_t data_i,
    input read_i,
    input write_i,
    input [VC_SIZE-1:0] vc_new_i,
    input vc_valid_i,
    input port_t out_port_i,
    input rst,
    input clk,
    output flit_t data_o,
    output logic is_full_o,
    output logic is_empty_o,
    output logic on_off_o,
    output port_t out_port_o,
    output logic vc_request_o,
    output logic switch_request_o,
    output logic vc_allocatable_o,
    output logic [VC_SIZE-1:0] downstream_vc_o,
    output logic error_o
);
```

一个 `input_buffer` 对应一个输入 VC；`input_port` 在每个输入端口中生成 4 个实例（VC0–VC3）。信号的流向如下：

| 信号 | 含义 |
| --- | --- |
| `data_i`、`write_i` | `input_port` 已按输入 flit 的 `vc_id` 选中的写数据和写请求。 |
| `read_i` | switch allocator 已选中该 VC 后发出的读请求。 |
| `out_port_i` | HEAD 的路由计算结果；写入 packet 元数据。 |
| `vc_new_i`、`vc_valid_i` | VC allocator 返回的下游 VC 分配结果。 |
| `data_o` | 当前队首 flit，附带已分配的下游 VC 编号，送往 crossbar。 |
| `out_port_o`、`downstream_vc_o` | 当前队首 packet 的目标输出端口和下游 VC，送往 switch allocator。 |
| `vc_request_o` | 队首 packet 未获得下游 VC 时，请求 VC allocator。 |
| `switch_request_o` | 队首 packet 已获得下游 VC 且有 flit 时，请求 switch allocator。 |
| `is_full_o`、`is_empty_o`、`on_off_o` | 内部 `circular_buffer` 的直接输出。 |
| `vc_allocatable_o`、`error_o` | 本模块自行产生：包尾成功发出时的释放脉冲、非法操作的错误脉冲。 |

## 2. packet 元数据类型（第 26–37 行）

```systemverilog
// Original single-packet FSM kept for reference; replaced by packet metadata FIFO.

typedef struct packed {
    port_t out_port;
    logic [VC_SIZE-1:0] downstream_vc;
    logic vc_allocated;
} packet_meta_t;

localparam [31:0] META_POINTER_SIZE = $clog2(BUFFER_SIZE);
```

旧实现只有一组路由/下游 VC 状态，因此一个 VC 在前一包结束前不能接收下一包。现在每个 packet 具有一个 `packet_meta_t`：

| 字段 | 含义 | 什么时候有效 |
| --- | --- | --- |
| `out_port` | 该包应走的本路由器输出端口 | HEAD/HEADTAIL 被接收时写入。 |
| `downstream_vc` | 该包在下游路由器应进入的 VC | VC allocator 授权后写入。 |
| `vc_allocated` | `downstream_vc` 是否已经有效 | 0 时请求 VC allocator；1 时允许请求 switch allocator。 |

`packed` 将上述字段连续打包，使 `meta_mem[i]` 是一个完整 packet 的控制状态。它不保存 HEAD/BODY/TAIL 实际数据，实际 flit 存在下一节的环形缓冲区。

## 3. 内部信号与两个存储结构（第 39–80 行）

```systemverilog
logic read_cmd, write_cmd;

packet_meta_t meta_mem[BUFFER_SIZE-1:0];
logic [META_POINTER_SIZE-1:0] meta_rd_ptr;
logic [META_POINTER_SIZE-1:0] meta_wr_ptr;
logic [META_POINTER_SIZE:0] num_packets;

logic meta_push_cmd;
logic meta_pop_cmd;
logic meta_alloc_cmd;
logic meta_full;
logic meta_space_available;
logic has_packet;
logic head_allocated;
logic accept_write;
logic accept_read;
logic write_packet_open;
logic write_order_ok;
logic is_head_flit;
logic is_headtail_flit;
logic is_body_flit;
logic is_tail_input_flit;
logic is_tail_flit;
packet_meta_t meta_head;
flit_novc_t read_flit;
```

这里有两套独立队列：

```text
circular_buffer：按 flit 排队，保存 HEAD/BODY/TAIL 数据
meta_mem       ：按 packet 排队，保存该包的路由和下游 VC 状态
```

`meta_rd_ptr` 指向当前待发送的队首 packet；`meta_wr_ptr` 指向下一个新 HEAD 的写入位置；`num_packets` 是当前排队包数。

`write_packet_open` 只描述**写入侧**：已经接收 HEAD、尚未接收该包 TAIL 时为 1。它不是“packet 正在发送”或“已分配下游 VC”的标志。

## 4. flit 环形缓冲区实例（第 82–98 行）

```systemverilog
circular_buffer #(
    .BUFFER_SIZE(BUFFER_SIZE)
)
circular_buffer (
    .data_i(data_i),
    .read_i(read_cmd),
    .write_i(write_cmd),
    .rst(rst),
    .clk(clk),
    .data_o(read_flit),
    .is_full_o(is_full_o),
    .is_empty_o(is_empty_o),
    .on_off_o(on_off_o)
);
```

此处直接说明信号归属：

- `is_full_o`、`is_empty_o`、`on_off_o` 都由 `circular_buffer` 更新，`input_buffer` 只是连接并使用它们；
- `read_flit` 是内部 flit FIFO 的队首 peek 数据；
- `read_cmd/write_cmd` 并不是原始 `read_i/write_i`，而是后面判定合法后的接受命令。

`on_off_o` 是环形 FIFO 的带迟滞上游流控输出：它不等于 `~is_full_o`，本模块也不重新计算它。

## 5. 已注释的旧单包 FSM（第 100–255 行）

这一整段历史代码不生效。它以 `IDLE → VA → SA` 管理一个 VC：HEAD 进入 VA、分配下游 VC 后进入 SA、TAIL 被读出后才回 IDLE。

其局限是：在一个 packet 的 TAIL 被读出前，后续 HEAD 会被当作错误，无法在同一个 VC 中排队多个 packet。当前 `meta_mem` 用“一包一项元数据”替代这一单一 FSM 状态。

## 6. 组合判定：什么是一个合法 packet 操作（第 257–281 行）

```systemverilog
assign meta_full = (num_packets == BUFFER_SIZE);
assign meta_space_available = ~meta_full | meta_pop_cmd;
assign has_packet = (num_packets != 0);
assign meta_head = meta_mem[meta_rd_ptr];
assign head_allocated = has_packet & meta_head.vc_allocated;
assign is_head_flit = (data_i.flit_label == HEAD) | is_headtail_flit;
assign is_headtail_flit = (data_i.flit_label == HEADTAIL);
assign is_body_flit = (data_i.flit_label == BODY);
assign is_tail_input_flit = (data_i.flit_label == TAIL);
assign is_tail_flit = (read_flit.flit_label == TAIL) | (read_flit.flit_label == HEADTAIL);

assign accept_read = read_i & head_allocated & ~is_empty_o;
assign write_order_ok = ((data_i.flit_label == HEAD) & ~write_packet_open & meta_space_available) |
                        (is_headtail_flit & ~write_packet_open & meta_space_available) |
                        (is_body_flit & write_packet_open) |
                        (is_tail_input_flit & write_packet_open);
assign accept_write = write_i & (~is_full_o | accept_read) & write_order_ok;
assign meta_push_cmd = accept_write & is_head_flit;
assign meta_pop_cmd = accept_read & is_tail_flit;
assign meta_alloc_cmd = vc_valid_i & has_packet & ~meta_head.vc_allocated;
```

按代码顺序理解这些判定：

1. `meta_head` 取元数据队首；只有它获得下游 VC（`head_allocated=1`）才允许读/发送。
2. `accept_read` 要求：switch allocator 已给出 `read_i`、队首已分配下游 VC、flit FIFO 非空。
3. `write_order_ok` 要求 flit 标签顺序正确：没有开放包时只能接收 HEAD/HEADTAIL；开放包时只能接收 BODY/TAIL。因此 `HEAD(A) → BODY(A) → HEAD(B)` 的最后一项会被拒绝。
4. `accept_write` 还要求 flit FIFO 未满；若已满，只有同拍 `accept_read=1` 才允许“读一个、写一个”。
5. HEAD/HEADTAIL 成功写入时 `meta_push_cmd=1`；TAIL/HEADTAIL 成功读出时 `meta_pop_cmd=1`。
6. `meta_alloc_cmd` 表示 VC allocator 正向一个确实等待分配的队首包返回结果。

这里的标签判断只能保证顺序，不能检验 BODY/TAIL 的语义 packet ID；发送端必须连续发送同一 packet 的 flit。板级发生器通过 `packet_active/active_packet_id/active_flit_index` 保存当前包来遵守这个协议。

## 7. 时序更新：何时真的写入、分配和弹出（第 283–348 行）

```systemverilog
always_ff @(posedge clk, posedge rst)
begin
    if(rst)
    begin
        meta_rd_ptr <= 0;
        meta_wr_ptr <= 0;
        num_packets <= 0;
        write_packet_open <= 0;
        vc_allocatable_o <= 0;
        error_o <= 0;
    end
    else
    begin
        vc_allocatable_o <= meta_pop_cmd;
        error_o <= (write_i & ~accept_write) |
                   (read_i & (~head_allocated | is_empty_o)) |
                   (vc_valid_i & (~has_packet | meta_head.vc_allocated));
```

复位后没有 packet、没有开放写入包。正常运行时：

- `vc_allocatable_o` 是 `meta_pop_cmd` 的寄存器脉冲；只有 TAIL/HEADTAIL 成功读出才为 1，表示一个包结束；
- `error_o` 是本拍非法写、非法读或非法 VC 授权的寄存器脉冲；下一拍没有错误则清零；
- 这两个信号**不是** `circular_buffer` 输出，而是本模块在此时序块生成。

第 302–321 行更新队首授权、新包元数据和写侧包边界：

```systemverilog
if(meta_alloc_cmd)
begin
    meta_mem[meta_rd_ptr].downstream_vc <= vc_new_i;
    meta_mem[meta_rd_ptr].vc_allocated <= 1'b1;
end

if(meta_push_cmd)
begin
    meta_mem[meta_wr_ptr].out_port <= out_port_i;
    meta_mem[meta_wr_ptr].downstream_vc <= {VC_SIZE{1'b0}};
    meta_mem[meta_wr_ptr].vc_allocated <= 1'b0;
end

if(accept_write)
begin
    if(data_i.flit_label == HEAD)
        write_packet_open <= 1'b1;
    else if(is_tail_input_flit | is_headtail_flit)
        write_packet_open <= 1'b0;
end
```

这三个 `if` 都在时钟上升沿执行，但它们维护的是三类不同状态。

### 7.1 第一个 `if`：把 VC allocator 的授权写回**当前队首包**

`meta_alloc_cmd` 的定义在第 281 行：

```systemverilog
meta_alloc_cmd = vc_valid_i & has_packet & ~meta_head.vc_allocated;
```

所以该 `if` 只有在以下三项同时成立时执行：

1. `vc_valid_i=1`：VC allocator 本拍确实返回授权；
2. `has_packet=1`：元数据 FIFO 中确有一个队首 packet；
3. `meta_head.vc_allocated=0`：该队首 packet 之前尚未获得下游 VC。

执行时写的是 `meta_mem[meta_rd_ptr]`，即队首而非新写入位置：

```systemverilog
meta_mem[meta_rd_ptr].downstream_vc <= vc_new_i;
meta_mem[meta_rd_ptr].vc_allocated <= 1'b1;
```

第一行保存本次获得的下游 VC 编号；第二行将其标记为有效。到下一周期，`head_allocated=1`，因此 `vc_request_o` 由 1 变为 0，而若 flit FIFO 非空，`switch_request_o` 会变为 1，开始竞争发送。它不会改变 `meta_rd_ptr/meta_wr_ptr/num_packets`，因为授权不是新包入队或旧包出队。

### 7.2 第二个 `if`：接收包头时，在**队尾**建立新 packet 元数据

`meta_push_cmd = accept_write & is_head_flit`，故只有 HEAD 或 HEADTAIL 已经被 `accept_write` 接受时才执行。写入位置是 `meta_mem[meta_wr_ptr]`，即元数据 FIFO 队尾：

```systemverilog
meta_mem[meta_wr_ptr].out_port <= out_port_i;
meta_mem[meta_wr_ptr].downstream_vc <= {VC_SIZE{1'b0}};
meta_mem[meta_wr_ptr].vc_allocated <= 1'b0;
```

- `out_port_i` 是 `rc_unit` 针对该 HEAD 算出的方向，写入后成为该新 packet 固定的路由方向；
- `downstream_vc` 先清 0，因为这个新包尚未得到 VC allocator 授权；此时 0 只是初始化值，不表示已经分到 VC0；
- `vc_allocated` 清 0，使该包在未来成为队首时可以发出 `vc_request_o`。

同一时钟沿的 `case({meta_push_cmd, meta_pop_cmd})` 会使 `meta_wr_ptr` 前移、`num_packets+1`。但新写入包如果排在已有包后面，不会立刻申请 VC allocator；只有它将来成为 `meta_rd_ptr` 指向的队首包才会申请。

### 7.3 第三个 `if`：只管理输入写入流的包边界

该块受 `accept_write` 保护，意味着**被拒绝的 flit 不会改变边界状态**：

```systemverilog
if(data_i.flit_label == HEAD)
    write_packet_open <= 1'b1;
else if(is_tail_input_flit | is_headtail_flit)
    write_packet_open <= 1'b0;
```

- 接收 HEAD：置 1。后续只允许 BODY/TAIL，禁止另一个 HEAD 插队；
- 接收 BODY：没有赋值，保持 1；
- 接收 TAIL：清 0，下一拍可以接收下一个 HEAD；
- 接收 HEADTAIL：不先置 1 而是保持/清为 0，因为这个单 flit 包在同拍就已经完整接收。

`write_packet_open` 只保证标签顺序连续；它不记录 packet ID，也不表示该包是否已获得下游 VC 或是否已经被发送。

第 323–346 行根据 push/pop 前移元数据指针：

```systemverilog
unique case({meta_push_cmd, meta_pop_cmd})
    2'b10: begin
        meta_wr_ptr <= increase_meta_ptr(meta_wr_ptr);
        num_packets <= num_packets + 1;
    end
    2'b01: begin
        meta_rd_ptr <= increase_meta_ptr(meta_rd_ptr);
        num_packets <= num_packets - 1;
    end
    2'b11: begin
        meta_wr_ptr <= increase_meta_ptr(meta_wr_ptr);
        meta_rd_ptr <= increase_meta_ptr(meta_rd_ptr);
        num_packets <= num_packets;
    end
    default: begin
        meta_wr_ptr <= meta_wr_ptr;
        meta_rd_ptr <= meta_rd_ptr;
        num_packets <= num_packets;
    end
endcase
```

### `case({meta_push_cmd, meta_pop_cmd})` 的四种情况

拼接顺序为 `{meta_push_cmd, meta_pop_cmd}`：高位是“新 packet 是否入队”，低位是“旧 packet 是否出队”。元数据 FIFO 的读写指针分别只应该在对应事件发生时移动，因此四种情况如下。

#### `2'b10`：只 push，新 packet 入队，旧 packet 不出队

```systemverilog
2'b10: begin
    meta_wr_ptr <= increase_meta_ptr(meta_wr_ptr);
    num_packets <= num_packets + 1;
end
```

条件是 `meta_push_cmd=1`、`meta_pop_cmd=0`：本拍成功接收 HEAD/HEADTAIL，但没有成功读出队首 TAIL/HEADTAIL。

```text
上升沿前：rd ─► [A，队首] ... wr ─► [空槽]
上升沿：  在 wr 写入新包 B 的元数据；wr 前移；包数 +1
上升沿后：rd 仍指向 A；B 排在队尾等待
```

`meta_rd_ptr` 没有在此分支赋值，因此保持原值；这是正确的，因为 A 尚未完成，队首不能改变。设计目的就是让后来的 B 能够先排队，但不改变 A 的发送顺序。

#### `2'b01`：只 pop，旧 packet 出队，没有新 packet 入队

```systemverilog
2'b01: begin
    meta_rd_ptr <= increase_meta_ptr(meta_rd_ptr);
    num_packets <= num_packets - 1;
end
```

条件是 `meta_push_cmd=0`、`meta_pop_cmd=1`：本拍成功读出队首的 TAIL/HEADTAIL，但没有接收新的 HEAD/HEADTAIL。

```text
上升沿前：rd ─► [A，队首] [B] ... wr ─► [空槽]
上升沿：  A 的元数据被逻辑弹出；rd 前移；包数 -1
上升沿后：rd ─► [B，新的队首]；wr 保持不变
```

`meta_wr_ptr` 保持原值，因为没有新 packet 需要写入。若 A 是唯一 packet，上升沿后 `num_packets=0`，此时 `rd` 和 `wr` 可能数值相同，但 `num_packets=0` 明确表示元数据 FIFO 为空。

#### `2'b11`：同拍 push 和 pop，一个进、一个出

`case` 的输入顺序是 `{meta_push_cmd, meta_pop_cmd}`，所以 `2'b11` 的准确条件是：

```systemverilog
meta_push_cmd = 1; // 本拍成功接收 HEAD 或 HEADTAIL，新 packet 入元数据队列
meta_pop_cmd  = 1; // 本拍成功读出队首的 TAIL 或 HEADTAIL，旧 packet 完成
```

例如上升沿到来前，元数据 FIFO 中只有前包 A，且本拍同时发生两件彼此独立的事：输出侧发送 A 的 TAIL，输入侧接收后包 B 的 HEAD。

```text
上升沿前：meta_rd_ptr ─► [ A，当前队首 ]   meta_wr_ptr ─► [ 空槽 ]

本拍组合判定：
  A 的 TAIL 被 switch allocator 选中并成功读取 → meta_pop_cmd=1
  B 的 HEAD 被 input buffer 成功接收          → meta_push_cmd=1

上升沿：
  ① 在旧 meta_wr_ptr 指向的空槽写入 B 的 out_port，初始化 B.vc_allocated=0；
  ② meta_rd_ptr 前移，越过已结束的 A；
  ③ meta_wr_ptr 前移，指向 B 后面的下一空槽；
  ④ num_packets 保持不变：少了 A 一项，同时多了 B 一项。

上升沿后：meta_rd_ptr ─► [ B，新的队首 ]   meta_wr_ptr ─► [ 下一空槽 ]
```

若 A 后面原本还有 C，则结果是“弹出 A、保留 C、在队尾追加 B”；新的队首是 C，而不是 B。无论哪种情况，`num_packets` 都不应加一或减一，因为一个 packet 离开元数据队列的同时恰有一个 packet 进入。

这样的设计还使元数据 FIFO 即使处于满状态，也能在队首 TAIL 同拍弹出时接收一个新的 HEAD：`meta_space_available = ~meta_full | meta_pop_cmd` 会认可这个“释放一个、占用一个”的操作。它避免了在连续 packet 流中额外空等一拍。

#### `default`，即 `2'b00`：既不 push，也不 pop

```systemverilog
default: begin
    meta_wr_ptr <= meta_wr_ptr;
    meta_rd_ptr <= meta_rd_ptr;
    num_packets <= num_packets;
end
```

条件是没有成功接收 HEAD/HEADTAIL，且没有成功读出 TAIL/HEADTAIL。可能是本拍只写了 BODY、只读了 HEAD/BODY、没有请求，或请求被 `accept_write/accept_read` 拒绝。

这时 packet 的数量和边界都没有变化：BODY 属于已有 packet，不应新增元数据；HEAD/BODY 的读取也没有结束 packet，不应删除元数据。因此两个指针和 `num_packets` 都保持不变。

`unique case` 表示这四种二值组合彼此互斥且应覆盖全部情况，有助于仿真器检查意外的 X/重叠条件；其功能本质是用 push/pop 事件更新一个标准环形 FIFO 的读指针、写指针和计数器。

## 8. 组合输出：怎样连接 VC allocator、switch allocator 和 crossbar（第 350–365 行）

```systemverilog
always_comb
begin
    data_o.flit_label = read_flit.flit_label;
    data_o.vc_id = head_allocated ? meta_head.downstream_vc : {VC_SIZE{1'b0}};
    data_o.data = read_flit.data;

    out_port_o = has_packet ? meta_head.out_port : LOCAL;
    downstream_vc_o = head_allocated ? meta_head.downstream_vc : {VC_SIZE{1'b0}};

    vc_request_o = has_packet & ~meta_head.vc_allocated;
    switch_request_o = head_allocated & ~is_empty_o;

    read_cmd = accept_read;
    write_cmd = accept_write;
end
```

这段是模块对外行为的汇总：

| 队首状态 | `vc_request_o` | `switch_request_o` | 意义 |
| --- | ---: | ---: | --- |
| 无 packet | 0 | 0 | 没有请求。 |
| 有 packet，未分配下游 VC | 1 | 0 | 只向 VC allocator 申请资源。 |
| 有 packet，已分配且 FIFO 非空 | 0 | 1 | 可向 switch allocator 请求本周期发送。 |

`data_o` 取 `read_flit`，但将 VC allocator 分配的 `downstream_vc` 填入 `data_o.vc_id`。因此同一物理链路上即使有不同 packet 的 flit，接收端 `input_port` 也会用这个 `vc_id` 分发至不同 `input_buffer`。

## 9. 元数据指针回绕（第 367–373 行）

```systemverilog
function logic [META_POINTER_SIZE-1:0] increase_meta_ptr
    (input logic [META_POINTER_SIZE-1:0] ptr);
    if(ptr == BUFFER_SIZE-1)
        increase_meta_ptr = 0;
    else
        increase_meta_ptr = ptr + 1;
endfunction
```

该函数使 `meta_rd_ptr/meta_wr_ptr` 在最后一个元数据位置后回到 0，形成 packet 元数据环形 FIFO。`BUFFER_SIZE` 应至少为 2；参数为 1 时 `$clog2(BUFFER_SIZE)` 会产生零位宽指针风险。

## 10. `input_port` 如何选择这 4 个 input buffer

下面代码来自 `src/input_port_Xiugai2.sv` 第 111–127 行，是本模块 `write_i/read_i` 的来源：

```systemverilog
write_cmd = {VC_NUM{1'b0}};
if(valid_flit_i)
    write_cmd[data_i.vc_id] = 1;

read_cmd = {VC_NUM{1'b0}};
if(sa_valid_i)
    read_cmd[sa_sel_vc_i] = 1;

xb_flit_o = data_out[sa_sel_vc_i];
```

接收 flit 时，`data_i.vc_id` 选择 VC0–VC3 中的一个 `input_buffer`；发送时，switch allocator 的 `sa_sel_vc_i` 选择一个 `input_buffer` 读出。因此多个 packet 可在不同 VC 的独立 FIFO 中并存，但同一 VC 内必须遵循 HEAD 到 TAIL 的连续顺序。
