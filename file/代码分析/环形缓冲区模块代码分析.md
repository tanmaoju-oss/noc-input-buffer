# 环形缓冲区（`circular_buffer`）模块代码分析

分析对象：`src/circular_buffer_Xiugai3.sv`。本文结合现有代码说明 flit FIFO 的存储、读写、满空判断与 `on_off` 流控；没有修改设计 RTL。

## 1. 模块功能与层级位置

`circular_buffer` 是每个输入 VC 的 flit FIFO。它接收去掉 VC 标识的 `flit_novc_t`，按先进先出顺序保存；读取时给出队首 flit。它不决定路由、不申请下游 VC，也不仲裁交叉开关，只提供存储状态和流控状态。

调用层级为：

```text
router
 └─ input_block（每个输入端口一个）
     └─ input_port（每个端口内含 VC_NUM 个实例）
         └─ input_buffer（每个 VC 一个）
             └─ circular_buffer（每个 input_buffer 一个）
```

在 `src/input_buffer_src_circular_full.sv` 第 82–98 行，`input_buffer` 实例化该模块：

```systemverilog
circular_buffer #(
    .BUFFER_SIZE(BUFFER_SIZE)
)
circular_buffer (
    .data_i(data_i),
    .read_i(read_cmd),
    .write_i(write_cmd),
    .rst(rst),
    .clk(clk),
    .data_o(read_flit),
    .is_full_o(is_full_o),
    .is_empty_o(is_empty_o),
    .on_off_o(on_off_o)
);
```

这里的 `read_cmd/write_cmd` 不是外部原始读写请求，而是 `input_buffer` 检查包状态、VC 分配、满空条件之后生成的内部接受命令。

## 2. 参数和端口（第 3–16 行）

```systemverilog
module circular_buffer #(
    parameter BUFFER_SIZE = 8
)(
    input flit_novc_t data_i,
    input read_i,
    input write_i,
    input rst,
    input clk,
    output flit_novc_t data_o,
    output logic is_full_o,
    output logic is_empty_o,
    output logic on_off_o
);
```

| 信号 | 方向 | 含义 |
| --- | --- | --- |
| `data_i` | 输入 | 本周期准备写入的 flit；类型 `flit_novc_t`，不包含下游 VC 编号。 |
| `write_i` | 输入 | 写请求；被接纳后，在时钟上升沿把 `data_i` 写入队尾。 |
| `read_i` | 输入 | 读/出队请求；被接纳后，在时钟上升沿队首指针前移。 |
| `data_o` | 输出 | 当前 `read_ptr` 指向的队首 flit；组合输出，不等待 `read_i`。 |
| `is_full_o` / `is_empty_o` | 输出 | FIFO 状态寄存器。 |
| `on_off_o` | 输出 | 面向上游的带迟滞流控许可；1 表示允许继续注入，0 表示要求暂停。 |

`BUFFER_SIZE=8` 时，`$clog2(8)=3`，所以读写指针宽度为 3 bit、合法位置为 0–7。

## 3. 存储体、指针和计数器（第 18–32 行）

```systemverilog
flit_novc_t memory [BUFFER_SIZE-1:0];
localparam ON_OFF_LATENCY = 2;
localparam [31:0] POINTER_SIZE = $clog2(BUFFER_SIZE);

logic [POINTER_SIZE-1:0] read_ptr;
logic [POINTER_SIZE-1:0] write_ptr;

logic [POINTER_SIZE-1:0] read_ptr_next;
logic [POINTER_SIZE-1:0] write_ptr_next;
logic is_full_next;
logic is_empty_next;
logic on_off_next;

logic [POINTER_SIZE:0] num_flits;
logic [POINTER_SIZE:0] num_flits_next;
```

- `memory[0:BUFFER_SIZE-1]` 是实际 FIFO 存储数组；每个元素保存一个 `flit_novc_t`。
- `POINTER_SIZE=$clog2(BUFFER_SIZE)` 是读写指针位宽。`read_ptr` 指向当前队首，`write_ptr` 指向下一次写入位置；两者由 `increase_ptr()` 在到达末地址后回绕。
- `num_flits` 是当前已存 flit 数，比指针多一位宽，能够表示 `0` 到 `BUFFER_SIZE`。它不直接决定满/空，而是用于 `on_off_o` 的阈值流控。
- `ON_OFF_LATENCY=2` 是流控迟滞的容量阈值间隔，并非时钟周期延迟。对于默认 `BUFFER_SIZE=8`：写入后数量大于 `8-2=6`（即 7 或 8）时关闭 `on_off_o`；读取后数量小于 2（即 0 或 1）时重新打开。中间的 2–6 区间保持原状态，避免接近满/空时频繁切换流控。
- `read_ptr_next`、`write_ptr_next` 和 `num_flits_next` 是组合逻辑计算的下一拍值；时序块在下一个上升沿将它们写回对应寄存器。
- `is_full_next`、`is_empty_next` 是满/空标志的下一拍值；分别在合法写入和合法读取后由指针关系更新。
- `on_off_next` 是下一拍上游流控值；它由本拍操作后的 `num_flits_next` 与上述高、低水位共同决定。

## 4. 时序块：什么时候真正写 memory、更新 FIFO 状态（第 47–69 行）

```systemverilog
always_ff@(posedge clk or posedge rst)
begin
    if (rst)
    begin
        read_ptr    <= 0;
        write_ptr   <= 0;
        num_flits   <= 0;
        is_full_o   <= 0;
        is_empty_o  <= 1;
        on_off_o    <= 1;
    end
    else
    begin
        read_ptr    <= read_ptr_next;
        write_ptr   <= write_ptr_next;
        num_flits   <= num_flits_next;
        is_full_o   <= is_full_next;
        is_empty_o  <= is_empty_next;
        on_off_o    <= on_off_next;
        if((~read_i & write_i & ~is_full_o) | (read_i & write_i))
            memory[write_ptr] <= data_i;
    end
end
```

复位后 FIFO 为空、可写、且流控许可为 1。正常工作时，全部状态在同一个 `posedge clk` 提交。

memory 写入条件分两类：

```text
只写：read_i=0、write_i=1、当前不满
读写同时：read_i=1、write_i=1
```

第二类允许“满 FIFO 同周期读出一个、写入一个”：旧队首被读走，队尾位置写入新 flit，容量不变。这是维持满载吞吐率的关键。

## 5. 组合块：四种读写情形（第 85–128 行）

组合块首先给出当前队首：

```systemverilog
data_o = memory [read_ptr];
```

这意味着 `data_o` 是 peek（查看）信号。真正消费数据由 `read_i` 被接受并在时钟沿推进 `read_ptr` 完成。

随后 `unique if` 把控制分为四类。

### 5.1 只读且非空（第 88–95 行）

```systemverilog
if(read_i & ~write_i & ~is_empty_o)
begin
    read_ptr_next = increase_ptr(read_ptr);
    write_ptr_next = write_ptr;
    is_full_next = 0;
    update_empty_on_read();
    num_flits_next = num_flits - 1;
end
```

当前队首在本周期供 `data_o` 使用；上升沿之后读指针前移一格、计数减一。若前移后读写指针相等，`update_empty_on_read()` 将 `is_empty_next` 置 1。只要读走一个 flit，就必定不再是“满”。

### 5.2 只写且非满（第 96–103 行）

```systemverilog
else if(~read_i & write_i & ~is_full_o)
begin
    read_ptr_next = read_ptr;
    write_ptr_next = increase_ptr(write_ptr);
    update_full_on_write();
    is_empty_next = 0;
    num_flits_next = num_flits + 1;
end
```

上升沿把 `data_i` 写入旧 `write_ptr` 位置，随后 `write_ptr` 前移；写入后 FIFO 一定不为空。若新写指针追上读指针，`update_full_on_write()` 置满标志。

### 5.3 同时读写且非空（第 104–111 行）

```systemverilog
else if(read_i & write_i & ~is_empty_o)
begin
    read_ptr_next = increase_ptr(read_ptr);
    write_ptr_next = increase_ptr(write_ptr);
    is_full_next = is_full_o;
    is_empty_next = is_empty_o;
    num_flits_next = num_flits;
end
```

一进一出，存储量不变，两个指针都前移。空/满状态也保持原值：

- 原来满：同周期读出一个、写入一个，仍然满；
- 原来非空非满：容量不变，仍保持非空非满；
- 原来为空：该分支不接受，转入第 5.4 节的默认分支。

### 5.4 不被接受的操作（第 112–119 行）

```systemverilog
else
begin
    read_ptr_next = read_ptr;
    write_ptr_next = write_ptr;
    is_full_next = is_full_o;
    is_empty_next = is_empty_o;
    num_flits_next = num_flits;
end
```

包括空 FIFO 只读、满 FIFO 只写，以及空 FIFO 的同时读写。此分支不改变 FIFO 的指针、计数和标志。

## 6. `on_off_o`：带迟滞的上游流控（第 120–127 行）

```systemverilog
if(num_flits > num_flits_next & num_flits_next < ON_OFF_LATENCY)
    on_off_next = 1;
else if(num_flits < num_flits_next &
        num_flits_next > BUFFER_SIZE - ON_OFF_LATENCY)
    on_off_next = 0;
else
    on_off_next = on_off_o;
```

该逻辑不直接把 `on_off_o` 等同于“非满”，而是建立高、低两个阈值，避免缓冲区在临界容量附近频繁打开/关闭：

| 场景（`BUFFER_SIZE=8`、`ON_OFF_LATENCY=2`） | 条件 | 结果 |
| --- | --- | --- |
| 读取后余量很低 | `num_flits_next < 2`，即 0 或 1 | `on_off_o` 置 1，重新允许上游发送。 |
| 写入后容量很高 | `num_flits_next > 6`，即 7 或 8 | `on_off_o` 置 0，要求上游暂停。 |
| 中间区间 | 2–6 | 保持原值。 |

在 `router.sv` 中，`input_block` 输出的 `is_on_off_out` 经路由器接口回送到相邻上游路由器；上游的 `switch_allocator` 仅在目标下游 VC 的 `on_off_i` 为 1 时发起交换分配。因此 `on_off_o=0` 最终会阻止新的 flit 进入这个快满 FIFO。

## 7. 指针与满空辅助函数（第 130–149 行）

### 7.1 环形回绕：`increase_ptr`

```systemverilog
function logic [POINTER_SIZE-1:0] increase_ptr (input logic [POINTER_SIZE-1:0] ptr);
    if(ptr == BUFFER_SIZE-1)
        increase_ptr = 0;
    else
        increase_ptr = ptr+1;
endfunction
```

当指针到达最后一个存储位置时返回 0，否则加一。例如深度 8 的位置序列为 `0 → 1 → ... → 7 → 0`。显式比较而非只依赖位宽自然溢出，使非 2 的幂深度也能正确回绕。

### 7.2 只读后的空判断：`update_empty_on_read`

```systemverilog
if(read_ptr_next == write_ptr)
    is_empty_next = 1;
else
    is_empty_next = 0;
```

只读时写指针不动；若读指针前移后追上写指针，说明刚读取的是最后一个元素。

### 7.3 只写后的满判断：`update_full_on_write`

```systemverilog
if(write_ptr_next == read_ptr)
    is_full_next = 1;
else
    is_full_next = 0;
```

只写时读指针不动；若写指针前移后追上读指针，说明最后一个空槽刚被填满。由于“空”和“满”时指针都可能相等，代码必须额外保存 `is_empty_o/is_full_o` 来区分状态。

## 8. 与 `input_buffer` 的读写控制关系

当前多包 `input_buffer` 的有效控制位于 `src/input_buffer_src_circular_full.sv` 第 270–280、350–365 行：

```systemverilog
assign accept_read = read_i & head_allocated & ~is_empty_o;
assign accept_write = write_i & (~is_full_o | accept_read) & write_order_ok;
...
read_cmd = accept_read;
write_cmd = accept_write;
```

因此 circular buffer 实际收到的命令满足：

- 只有队首包已获下游 VC、且 FIFO 非空时才会收到读命令；
- FIFO 已满时，只有本周期同时有已接受读操作，才允许写入；
- `write_order_ok` 还限制 HEAD/BODY/TAIL 的包内写入顺序。

这层上游过滤保证该 FIFO 正常工作时不会遇到“空状态同时读写”的不一致请求。

## 9. 当前 RTL 的边界注意点

1. **`data_o` 在空时无有效性保证。** 它仍会读取 `memory[read_ptr]`，但数据可能是旧值或未初始化值；使用方必须以 `is_empty_o` 和实际读取许可判断，不可单独把 `data_o` 当有效 flit。

2. **空 FIFO 同时 `read_i=1, write_i=1` 不应直接使用。** 组合块会保持状态（第 5.4 节），但时序块的 `read_i & write_i` 条件仍会执行 memory 写入。当前 `input_buffer` 用 `accept_read` 过滤后不会向它送出该组合；若将来复用本模块，调用者也必须遵守这个限制，或应统一时序写使能与组合接受条件。

3. **满空主要由指针和标志判断，计数服务于流控。** `num_flits` 不直接驱动 `is_full_o/is_empty_o`，两套状态必须保持同步；现有四种接受操作正是在维护这一一致性。

## 10. 总结

`circular_buffer` 以读写指针保存每个输入 VC 的 flit 队列，以 `is_empty_o/is_full_o` 控制可接受的读写，以 `num_flits` 的双阈值生成 `on_off_o` 反馈。`input_buffer` 负责把包状态与 VC 分配条件转成合法的 `read_cmd/write_cmd`；该模块则在时钟沿完成 FIFO 数据和状态的实际更新。
