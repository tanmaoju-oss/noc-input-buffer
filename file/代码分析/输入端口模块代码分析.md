# 输入端口（`input_port`）模块代码分析

分析对象：`src/input_port_Xiugai2.sv`。本文按源码顺序说明当前生效逻辑。

## 模块功能与层级位置

`input_port` 对应 router 的一个**物理输入端口**。它接收一条链路每拍到达的 flit，根据 flit 携带的 `vc_id` 分发至该端口内的 4 个 `input_buffer`；同时把 VC allocator、switch allocator 和 crossbar 与这些 input buffer 连接起来。

```text
router
└─ input_block
   └─ input_port（一个物理输入端口）
      ├─ rc_unit：为到达 HEAD 计算输出方向
      └─ input_buffer × 4：VC0、VC1、VC2、VC3
```

本模块本身不存储 flit、不决定下游 VC、不直接仲裁竞争；它负责**分发、汇集和选择**。

## 1. 模块接口（第 3–32 行）

```systemverilog
module input_port #(
    parameter BUFFER_SIZE = 8,
    parameter X_CURRENT = MESH_SIZE_X/2,
    parameter Y_CURRENT = MESH_SIZE_Y/2
)(
    input flit_t data_i,
    input valid_flit_i,
    input rst,
    input clk,
    input [VC_SIZE-1:0] sa_sel_vc_i,
    input [VC_SIZE-1:0] va_new_vc_i [VC_NUM-1:0],
    input [VC_NUM-1:0] va_valid_i,
    input sa_valid_i,
    output flit_t xb_flit_o,
    output logic [VC_NUM-1:0] is_on_off_o,
    output logic [VC_NUM-1:0] is_allocatable_vc_o,
    output logic [VC_NUM-1:0] va_request_o,
    output logic sa_request_o [VC_NUM-1:0],
    output logic [VC_SIZE-1:0] sa_downstream_vc_o [VC_NUM-1:0],
    output port_t [VC_NUM-1:0] out_port_o,
    output logic [VC_NUM-1:0] is_full_o,
    output logic [VC_NUM-1:0] is_empty_o,
    output logic [VC_NUM-1:0] error_o
);
```

| 信号组 | 交互对象 | 作用 |
| --- | --- | --- |
| `data_i/valid_flit_i` | 上游链路 | 一条到达 flit；其中 `data_i.vc_id` 选择目标 input buffer。 |
| `va_request_o/out_port_o` | VC allocator | 各 VC 的下游 VC 请求和目标端口。 |
| `va_new_vc_i/va_valid_i` | VC allocator | 对各 VC 返回下游 VC 授权。 |
| `sa_request_o/out_port_o/sa_downstream_vc_o` | switch allocator | 各 VC 的本周期交换请求、方向和目标下游 VC。 |
| `sa_sel_vc_i/sa_valid_i` | switch allocator | 本输入端口本周期被选中的 VC 编号及有效标志。 |
| `xb_flit_o` | crossbar | 被选 VC 的队首 flit。 |

## 2. 中间信号（第 34–42 行）

```systemverilog
flit_novc_t data_cmd [VC_NUM-1:0];
flit_t [VC_NUM-1:0] data_out;
port_t out_port_cmd;
logic [VC_NUM-1:0] read_cmd;
logic [VC_NUM-1:0] write_cmd;
logic [VC_SIZE-1:0] sa_sel_vc_reg;
logic sa_valid_reg;
```

- `data_cmd[v]`：送给 VC `v` 的无 VC 编号 flit；原始 `data_i.vc_id` 已被用于选择数组位置，故数据本身不再需要该字段。
- `data_out[v]`：各 input buffer 的队首输出，最后只选择一个送往 crossbar。
- `read_cmd/write_cmd`：各 VC 的实际读写使能；同拍每组至多一个 bit 为 1。
- `out_port_cmd`：当前输入 flit 的路由结果；HEAD 写入时由对应 input buffer 锁存为 packet 元数据。
- `sa_sel_vc_reg/sa_valid_reg` 会寄存 switch allocator 的选择，但当前有效数据路径使用组合输入 `sa_sel_vc_i`，见第 6 节。

## 3. 生成 4 个 input buffer（第 44–72 行）

```systemverilog
for(vc=0; vc<VC_NUM; vc++)
begin: generate_virtual_channels
    input_buffer #(.BUFFER_SIZE(BUFFER_SIZE)) input_buffer (
        .data_i(data_cmd[vc]),
        .read_i(read_cmd[vc]),
        .write_i(write_cmd[vc]),
        .vc_new_i(va_new_vc_i[vc]),
        .vc_valid_i(va_valid_i[vc]),
        .out_port_i(out_port_cmd),
        .rst(rst), .clk(clk),
        .data_o(data_out[vc]),
        .is_full_o(is_full_o[vc]),
        .is_empty_o(is_empty_o[vc]),
        .on_off_o(is_on_off_o[vc]),
        .out_port_o(out_port_o[vc]),
        .vc_request_o(va_request_o[vc]),
        .switch_request_o(sa_request_o[vc]),
        .vc_allocatable_o(is_allocatable_vc_o[vc]),
        .downstream_vc_o(sa_downstream_vc_o[vc]),
        .error_o(error_o[vc])
    );
end
```

当前 `VC_NUM=4`，所以 elaboration 后形成 `input_buffer[0]` 至 `input_buffer[3]`。每一个都有独立 flit FIFO、独立 packet 元数据 FIFO和独立的 VC/switch 请求。不同 packet 若携带不同 `vc_id`，会进入不同的 input buffer，不会共享其内部队列。

## 4. 路由计算单元（第 74–87 行）

```systemverilog
rc_unit #(
    .X_CURRENT(X_CURRENT), .Y_CURRENT(Y_CURRENT),
    .DEST_ADDR_SIZE_X(DEST_ADDR_SIZE_X),
    .DEST_ADDR_SIZE_Y(DEST_ADDR_SIZE_Y)
) rc_unit (
    .x_dest_i(data_i.data.head_data.x_dest),
    .y_dest_i(data_i.data.head_data.y_dest),
    .flit_label_i(data_i.flit_label),
    .out_port_o(out_port_cmd)
);
```

`rc_unit` 根据本 router 坐标和 HEAD 的目的坐标输出 `out_port_cmd`。当输入是 BODY/TAIL 时，`rc_unit` 保持其已计算的方向；对应 input buffer 只在接收 HEAD/HEADTAIL 时把该方向写进新 packet 的元数据，因此 BODY/TAIL 不会重写路由。

## 5. 已寄存但当前未用于数据选择的 SA 信号（第 89–101 行）

```systemverilog
always_ff @(posedge clk or posedge rst)
begin
    if(rst)
    begin
        sa_sel_vc_reg <= {VC_SIZE{1'b0}};
        sa_valid_reg <= 1'b0;
    end
    else
    begin
        sa_sel_vc_reg <= sa_sel_vc_i;
        sa_valid_reg <= sa_valid_i;
    end
end
```

这段会保存上一拍 switch allocator 的选择。当前文件第 126 行为了连续 packet 的 flit 对齐，实际使用 `sa_sel_vc_i`，而不是 `sa_sel_vc_reg`；所以这两个寄存器现在不在 `xb_flit_o` 的有效选择路径上。

## 6. 写入分发、读取选择与 crossbar 输出（第 111–127 行）

```systemverilog
always_comb
begin
    data_cmd[data_i.vc_id].flit_label = data_i.flit_label;
    data_cmd[data_i.vc_id].data = data_i.data;

    write_cmd = {VC_NUM{1'b0}};
    if(valid_flit_i)
        write_cmd[data_i.vc_id] = 1;

    read_cmd = {VC_NUM{1'b0}};
    if(sa_valid_i)
        read_cmd[sa_sel_vc_i] = 1;

    xb_flit_o = data_out[sa_sel_vc_i];
end
```

这段是 input port 的核心。

### 写入

`data_i.vc_id` 选择唯一的目标 VC。若 `valid_flit_i=1`，仅 `write_cmd[data_i.vc_id]=1`，因此一个物理输入端口一拍最多向一个 input buffer 写一个 flit。

### 读取

`sa_valid_i=1` 表示 switch allocator 已为该输入端口选择一个 VC；仅 `read_cmd[sa_sel_vc_i]=1`，被选 input buffer 才会接受读/发送。

### 输出

`xb_flit_o` 取相同编号的 `data_out`。旧代码使用 `sa_sel_vc_reg`，会使数据选择相对当前仲裁结果滞后一拍；当前改为 `sa_sel_vc_i`，保证当前获得读取命令的 VC 与送入 crossbar 的 flit 一致。
